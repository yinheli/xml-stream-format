Format, query and browse XML that doesn't fit in memory.

A strict XML 1.0 formatter, XPath extractor and terminal browser. Events stream through a temporary disk tape — no DOM, no whole-document string — so memory stays flat while files grow to gigabytes.

Bounded memory

Validated events go to a private on-disk tape and are replayed. A slow consumer pauses reads; temp data is removed on finish, error or abort.

Strict by default

XML 1.0 via Expat (WASM). DOCTYPE and entities are rejected — no network or file loading. Strict UTF-8/16, ASCII and Latin-1 decoding.

Validate before output

The whole input is checked before the first byte is written. Invalid XML never produces partial output.

Instant terminal browser

view shows the first screen of a multi-GB file before EOF. Loading is demand-driven; folding, fuzzy search, copy and export included.

XPath 3.1

FontoXPath over an on-demand DOM in a worker, with heap and time budgets. Extract matches as standalone, namespace-complete XML.

Streaming hooks

Rename, rewrite or drop elements, attributes and text while formatting. Results are re-parsed so hooks cannot inject markup.

CLI

# format (validates first, never overwrites)
xml-stream-format huge.xml -o pretty.xml
cat huge.xml | xml-stream-format --reindent

# extract XPath matches as XML
xml-stream-format extract huge.xml \
  --xpath '//order[@status="returned"]'

# browse in the terminal
xml-stream-format view huge.xml

API

import { createReadStream } from 'node:fs';
import { formatXml, openXml } from 'xml-stream-format';

const input = () => createReadStream('in.xml');
for await (const chunk of formatXml(input()))
  process.stdout.write(chunk);

const doc = await openXml(input());
const [hit] = await doc.select('//order[1]');
for await (const xml of doc.extract(hit.xpath))
  process.stdout.write(xml);
await doc.close();
